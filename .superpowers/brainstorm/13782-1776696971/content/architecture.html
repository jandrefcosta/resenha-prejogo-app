Arquitetura do Bolão

Seção 1 de 4 — Estrutura geral, rotas e dados

Rotas de página

/bolao — estrutura de navegação
/bolao — hub: ranking global + lista de bolões privados do usuário
/bolao/[id] — bolão privado: ranking interno + link para palpites
/bolao/palpites — grid de palpites (R1/R2/R3) — mesmo para global e privado
/bolao/novo — criar novo bolão privado (nome + código gerado)

Modelo de dados Redis

Chaves Redis (namespace bolao:*)
bolao:global:ranking  → Sorted Set (userId → totalPts) — ranking global
bolao:{id}:meta  → JSON (nome, código, adminId, criadoEm)
bolao:{id}:members  → Set (userIds)
bolao:{id}:ranking  → Sorted Set (userId → totalPts)
bolao:code:{code}  → String (bolaoId) — lookup por código convite
bolao:user:{userId}:boloes  → Set (bolaoIds) — bolões do usuário
palpite:{userId}:{fixtureId}  → JSON ({home, away, locked, ts})
score:{userId}:{fixtureId}  → JSON ({pts, outcome}) — após jogo encerrado

API Routes

Endpoints /api/bolao/*
POST /api/bolao — criar bolão privado
POST /api/bolao/join — entrar por código de convite
GET /api/bolao/[id] — meta + ranking do bolão
GET /api/bolao/me — bolões do usuário logado
GET /api/bolao/global — ranking global (top 50 + posição do usuário)
PUT /api/palpites/[fixtureId] — salvar/atualizar palpite (auth required)
GET /api/palpites — todos os palpites do usuário logado
POST /api/bolao/score — endpoint do cron (calcular pontos)

Cron de pontuação

Vercel Cron a cada 30 minutos — chama /api/bolao/score com secret header. Para cada jogo com status finished e palpites ainda não pontuados: calcula pts, grava score:{userId}:{fixtureId}, atualiza Sorted Sets do ranking global e de todos os bolões privados onde o usuário participa.
